# GreekGod 4.0 Offline AI Pack release record

Status: Phase 3 implementation and isolated physical import smoke complete on
2026-09-22. This record selects the production AI asset and distribution
boundary; it does not approve the remaining platform/signing release gates.

## Release decision

Local AI is optional. The base GreekGod installer contains neither a GGUF nor
the llama.cpp runtime. GreekGod 4.0 has no model/runtime downloader, production
URL, Ollama integration, cloud fallback, or hosting-provider dependency for AI
installation. Tracking, workouts, journal, analytics, and reports remain usable
with no AI assets installed.

AI is delivered as a separate, manually transported `GreekGod Offline AI Pack
4.0.0`. The user may copy it by USB, external disk, LAN share, or any other
out-of-band method, then select its local folder in Settings. GreekGod verifies
the source, streams a copy into its per-user managed root, verifies the
destination, and atomically activates it. Inference is fully offline after
installation.

## Authoritative contract and layout

The single checked-in authority is
`apps/desktop/src-tauri/ai-pack/greekgod-ai-pack-4.0.json`. The application,
builder, standalone verifier, and tests consume that contract. Manifest format
is 1, pack ID is `com.igorpich.greekgod.offline-ai-pack`, compatibility is
GreekGod release line 4.0 on `windows-x86_64`, and payload is exactly 30 trusted
files plus `manifest.json`:

- `model/Phi-3.5-mini-instruct-2fe19245-Q4_0.gguf`;
- `runtime/`: exactly 24 llama.cpp b10760 files;
- `legal/`: four required license/notice files;
- `provenance/phi-3.5-provenance.json`.

Selected model source is `microsoft/Phi-3.5-mini-instruct` revision
`2fe192450127e6a83f7441aef6e3ca586c338b77`, Q4_0, 2,176,177,152 bytes,
SHA-256
`3913ce8d702ec0cb053c2c5238c4438596f2da99ecab56480e252f20580673db`.
The runtime is llama.cpp b10760 commit
`0f3a71be15af836d277c9f918adfafb45732677e`; every one of its 24 files is
size/hash pinned in the same contract.

The former GGUF hash
`b5374915da534cb93df39f03bd4f2cd5a0c533df0d5e21957dc9556c260be9eb`
remains qualification history only. It is not accepted by the 4.0 production
contract; a legacy manual layout is reported as `MODEL_OUTDATED` and is not
deleted or executed.

The per-user managed root is the application local-data directory plus
`companion-managed-runtime`. Imported content is copied into a new inactive
`packs/install-<128-bit-random-hex>/` directory. It becomes authoritative only
when the verified `active-pack.json` pointer is atomically replaced. Failed,
cancelled, interrupted, insufficient-space, source-change, or corrupt imports
leave the previously active pack intact. Cleanup is limited to inactive
`install-*` content inside GreekGod-owned `staging` and `packs` directories;
symlinks and Windows reparse points are rejected. Hashing and copying use a
1 MiB streaming buffer, so the 2.176 GB model is never loaded into memory as a
whole. No executable is launched from the selected external source directory.

## Verification record

The real pack assembled from the qualified local inputs passed the standalone
verifier with 30/30 trusted payload files. The isolated Desktop smoke used the
test-only identifier `com.igorpich.formlog.aipacksmoke` and a separate temporary
managed root outside production storage.

The actual Settings folder picker and import path were exercised. Before import,
the tracker loaded with zero entries, Companion was gracefully unavailable, and
no sidecar existed. Import progress remained visible while source verification,
streaming copy, and destination verification ran. Activation produced
`READY_UNLOADED`; the installed model hash matched the selected SHA-256 and all
24 runtime files matched the contract. `Testuj lokalnie` reached `READY_WARM`,
including authenticated loopback readiness and invalid-token rejection, and a
real Companion response was rendered.

After full application restart, the installed pack was recognized as
`READY_UNLOADED`, no sidecar existed before AI use, and a second real Companion
inference completed. Importing a deliberately corrupted copy (one added byte in
`runtime/ggml.dll`) was rejected as `RUNTIME_INVALID`; `active-pack.json` was
unchanged and the previous valid pack still reached `READY_WARM`. Application
shutdown left no smoke sidecar. Production AppData was not read or modified.

The approved physical 300-second idle-unload measurement from the unchanged
managed-runtime lifecycle remains applicable and was not repeated in this Phase
3 smoke. Shutdown/no-orphan behavior was physically repeated twice.
