# GreekGod PC 4.0 Desktop and manual-private release policy

Decision date: 2026-09-28. Policy status: **MANUAL_PRIVATE SELECTED**.

## Release-track boundary

GreekGod PC 4.0 is the Desktop release line. The existing GreekGod Mobile
application is a separate product/release track and is not part of the PC 4.0
release gate. Future significant mobile work belongs to the independently
managed GreekGod Mobile 2.0 line. Android signing, distribution, packaging, UX,
and feature work will not be performed during PC 4.0 finalization.

The final release cut sets the root PC authority, Desktop, Sync Service, and the
shared sync service-version crate to `4.0.0`. Mobile remains independently at
`4.0.0-rc.1` with Android versionCode `3000003`. Root `build`, `typecheck`, and
`test` commands still aggregate both workspaces as regression coverage, but no
runtime or packaging mechanism includes Mobile in the PC installer. A release
guard enforces this explicit divergence for the PC 4.0.0 cut.

## Manual private update and distribution

GreekGod PC 4.0 performs no automatic update discovery or periodic version
check, contains no production update URL, downloads no installer, and has no
updater daemon, background update task, update server, or hosting dependency.
The application remains functional indefinitely without an update service or
network connectivity.

The owner distributes an exact installer through a trusted, owner-controlled
out-of-band path such as USB, external disk, LAN, or manual file sharing. The
user initiates an update by launching that trusted newer installer. The audited
current-user NSIS `UpdateMode` path replaces the older installed application in
place. AppData and the database remain outside installer replacement. The final
installer SHA-256 is the integrity identifier supplied with the privately
distributed artifact.

Windows distribution remains `PRIVATE_UNSIGNED`: public-trust Authenticode is
waived for this private/limited release, the owner accepts `Unknown publisher`
and possible SmartScreen warnings, and all non-signature integrity gates remain
mandatory. The optional Offline AI Pack is transported separately and manually;
no AI assets or network downloader are included in the base installer.

## Automatic-updater audit

Production Desktop dependencies, Cargo/npm locks, Tauri configuration,
capabilities, frontend/native runtime source, and installer configuration were
audited. No Tauri updater plugin, updater endpoint, update manifest, GitHub
Releases auto-update path, periodic check, scheduled updater, installer
downloader, or update-related cloud dependency exists.

Classified non-updater findings:

- NSIS `UpdateMode` is the local in-place path entered only after the user runs
  a newer installer;
- managed Companion HTTP is authenticated loopback communication with the local
  AI sidecar;
- the frontend `fetch(dataUrl)` converts an already-local data URL;
- `acquire-llama-runtime.ps1` is explicit development/release acquisition
  tooling and is neither shipped runtime behavior nor an application updater.

The versioned guard at `tools/windows-release/verify-manual-private-policy.mjs`
fails on updater dependencies/configuration, production updater primitives or
unclassified runtime networking, install-mode drift, AI assets in the base
installer, weakened AppData upgrade protection, signing-policy drift, or
protocol/schema compatibility drift.

The signing guard correctly rejected the non-clean historical Cargo target,
which also contains older installers and preview/test executables. It passed on
an isolated surface containing only the current Desktop executable, Sync Service
executable, and NSIS installer. Final promotion must likewise use a clean exact
release surface and record the SHA-256 of the exact final installer.

## Existing Mobile compatibility

PC 4.0 retains sync protocol 1 and schema 8. The existing Mobile client also
requires protocol 1/schema 8, uses the separate
`com.igorpich.greekgod.mobile` identifier, and remains wire/domain compatible.
Mobile regression tests/build are compatibility evidence only; they do not
qualify or release GreekGod Mobile 2.0.

## PC 4.0 blocker audit

The following PC 4.0 areas are closed or non-blocking: real 3.0.3 upgrade and
schema migration, deterministic Analytics/HumanCoach foundation, local
Companion production runtime, authoritative Phi provenance and selected model,
Offline AI Pack, MSVC/UCRT, private unsigned Windows policy, installer upgrade
UX, Android removal from PC scope, and manual-private distribution/update
policy.

Subject to the validation recorded with this decision, no known PC 4.0 release
blocker remains before explicit product-owner approval for final version
promotion. Post-4.0 feature backlog is not a release blocker.
