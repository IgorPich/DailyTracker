# GreekGod 4.0 Windows native runtime policy

Status: **CLOSED** on 2026-09-27. Policy and packaging implementation are
complete, and the exact distribution passed external clean-Windows validation.

## Audited scope and result

The production-authority Desktop executable, production Sync Service executable,
and all 23 PE files in the approved 24-file llama.cpp b10760 runtime were inspected
statically with the Visual Studio 2022 x64 `dumpbin`. The remaining runtime file
is the LLVM OpenMP license. `llama-quantize.exe` is not present in the authoritative
pack contract and is not distributed. The exact hashes, imports, architecture and
per-import classifications are recorded in
`4.0.0-windows-native-dependency-inventory.json`.

- Desktop imports Windows system DLLs and Windows UCRT API sets. It has no direct
  `MSVCP140*`, `VCRUNTIME140*` or `CONCRT140` import.
- Sync Service additionally imports exactly `VCRUNTIME140.dll`.
- The b10760 runtime additionally imports exactly `MSVCP140.dll`,
  `VCRUNTIME140.dll`, and `VCRUNTIME140_1.dll`.
- `libomp.dll` is already one of the 24 pinned runtime files.
- `ggml-vulkan.dll` imports driver-provided `vulkan-1.dll`. It is not copied from
  Windows or treated as an MSVC prerequisite.
- No unexpected/unresolved dependency was found in the static inventory.

## Supported baseline and selected policy

GreekGod 4.0 supports Windows 10/11 x64. The Windows Universal CRT and
`api-ms-win-crt-*` API-set resolution are treated as supported-OS components;
GreekGod does not redistribute Windows system or API-set DLLs.

The selected solution is **Policy B: app-local redistribution of exact pinned
Microsoft VC runtime DLLs**. This is the smallest measured set and preserves the
current-user, local-first installation model without an administrative or network
prerequisite:

- base installer: `vcruntime140.dll` for Sync Service;
- optional Offline AI Pack: `msvcp140.dll`, `vcruntime140.dll`, and
  `vcruntime140_1.dll` beside the llama.cpp executables/DLLs.

The checked authority is
`apps/desktop/src-tauri/windows-native-runtime/greekgod-windows-native-runtime.json`.
Build preparation, the base bundle, the AI Pack builder/verifier, and runtime
verification consume that one contract. No Microsoft binary is committed to git.
The release build copies only verified inputs from the exact official Visual
Studio redist directory; size/hash mismatches and arbitrary substitutions fail.
There is no download path.

Authoritative source is Microsoft Visual Studio Build Tools 2022 17.14.37,
`VC/Redist/MSVC/14.44.35112/x64/Microsoft.VC143.CRT`, x64 file version
14.44.35211.0:

native payload changes; the application does not silently accept a newer or
different app-local DLL.

## Failure and component boundaries

The Sync Service lifecycle verifies the adjacent manifest and exact app-local
base DLL before executing its version handshake. Missing/altered files report
`NATIVE_PREREQUISITE_MISSING` or `NATIVE_PREREQUISITE_INVALID` instead of an
opaque loader failure.

The optional AI Pack treats all three files as trusted `NATIVE_PREREQUISITE`
payloads. A missing or altered prerequisite prevents activation/execution with a
distinct diagnostic. It does not become `MODEL_MISSING`, does not delete the
previous active pack, does not start AI, does not fall back to Ollama/cloud, and
does not affect tracker, workouts, journal, analytics, reports, HumanCoach or
sync storage.

WebView2 is separate from this policy. GreekGod does not override Tauri's
`webviewInstallMode`; Tauri CLI 2.11.4 therefore uses its existing default
`downloadBootstrapper` policy when WebView2 setup is required. No WebView2 DLL
appeared in these PE imports and no WebView2 asset or installer behavior was
changed in Phase 4. That pre-existing WebView2 installer/network boundary is not
part of the MSVC/UCRT solution.

## Validation record

The local host has no usable Windows Sandbox executable, Docker, VirtualBox,
VMware, Hyper-V tooling, or other approved disposable Windows 10/11 x64 runner.
No optional feature was enabled and no system-wide prerequisite was installed.
Static import inspection, pinned-source verification, builds, deterministic
negative tests, isolated current-host app-local execution and AI inference can
provide supporting evidence, but by themselves could not prove absence of
reliance on this developer machine's installed runtime.

Supporting current-host results:

- the final Offline AI Pack verified 33/33 payload files;
- real b10760 readiness and inference passed; the running process loaded all
  three VC DLLs from the pack runtime directory and left no orphan;
- a controlled copy without `msvcp140.dll` failed as
  `NATIVE_PREREQUISITE_MISSING`, while the original pack stayed valid;
- an isolated Sync Service copy passed native preflight, stayed running, and
  loaded `vcruntime140.dll` from its own directory; its missing-DLL copy failed
  with the same distinct missing-prerequisite class;
- the NSIS payload contains only `greekgod.exe`, Sync Service, lifecycle script,
  native contract, and the exact base `vcruntime140.dll`; it contains no other

## Phase 4B portable validation kit

The Policy B implementation is complete. Repository tooling under
`tools/windows-native-validation-kit/` builds a portable directory outside the
repository from the exact pinned installer and verified 33-file Offline AI Pack.
The kit contains a read-only preflight, PS5.1-compatible pack verification,
runtime module-origin checks, no-orphan check, sanitized JSON evidence collector,
and an eleven-step operator README. Installer, GGUF, runtime binaries and generated
evidence remain outside git.

Local kit assembly and self-test passed. The development-host preflight was run
only with `APPDATA` and `LOCALAPPDATA` redirected to an empty isolated directory;
it correctly classified the host as `CONTAMINATED_FOR_STRICT_TEST`, while
validating the installer, AI Pack, x64 platform, VC runtime discovery and WebView2
discovery. Synthetic evidence collection passed without emitting user or machine
identity. The later external physical PASS described above closes the strict
clean-Windows sub-gate.
