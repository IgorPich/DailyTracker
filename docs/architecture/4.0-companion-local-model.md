# GreekGod 4.0 local Companion model

Status: feature implementation, stop for review. Foundation is `86973d92185dedfe9c63889ef76060a50dd472a4`; the pre-LLM checkpoint remains `56ecc53ceb670ea12df06984269f61e33baedec2`.

## Boundary and deployment decision

`RealLocalCompanionModel` is a Desktop/infrastructure adapter over the provider-neutral `LocalInferenceRuntime`. It receives one already-bounded request and returns untrusted JSON. It has no AppData, SQLite, Analytics, identity, registry, command gateway, repository, memory acceptance or presentation capability. Existing application validators remain authoritative after the adapter. FakeCompanionModel remains the default for deterministic tests and the existing memory/explicit-command demonstration screens.

`OllamaDevelopmentRuntime` remains an optional development/benchmark integration for this PC. The feature branch also implements a current-user managed llama.cpp Vulkan sidecar behind the same seam. It pins b10760/`0f3a71be15af836d277c9f918adfafb45732677e`, verifies a minimal complete loadable inventory, binds a dynamic authenticated loopback endpoint, and uses raw completion. It never installs system-wide, changes PATH, registers a service, downloads a model, or commits a runtime/weight binary. Packaging/signing and review remain release gates; this branch is not approved for foundation yet.

The first UI integration is deliberately narrow: TrainerText can request transient review drafts through the real adapter. A failed/missing model shows an error and cannot write. The Settings card reports readiness and offers a read-only synthetic test. Tracking, HumanCoach persistence, Companion Memory persistence and the command gateway remain independent.

Its development-only provider locator is the Ollama tag `phi3.5:latest`, but that mutable locator is never trusted as identity: readiness requires the exact evaluated manifest SHA-256 `61819fb370a3c1a9be6694869331e5f85f867a079e9271d66cb223acb81d04ba`. Missing tag is `MODEL_MISSING`; a different digest is `CHECKSUM_MISMATCH`; an unreachable endpoint is `RUNTIME_UNAVAILABLE`. A future managed runtime must additionally report `UNSUPPORTED_HARDWARE` before inference. No silent download or substitution is allowed.

Ollama stores assets in its user-owned cache for this benchmark; its manifest digest binds the model-layer digest and Ollama verified the layer when pulled. The eventual managed sidecar must use the defined versioned per-user GreekGod path and independently verify the full GGUF checksum before startup. The path and checksum must not be stored in Tracking data.

## Prompt, validation and failure contract

Transport wrapper `greekgod-companion-v1` carries four request-specific contracts: `greekgod-trainer-v2`, `greekgod-dialogue-v2`, `greekgod-memory-v2`, and `greekgod-command-v2`. Only the request-specific text, explicit entity candidates and selected evidence cross the seam. Exact labels and IDs are JSON data. Full AppData, history, unrelated HumanCoach items, memory collections, credentials and sync material are never included.

The runtime receives a closed JSON schema, temperature zero and a bounded token budget. Before returning anything, the adapter applies request-specific closed validation for exact fields, types, bounds, enums, duplicate/unknown/out-of-allowlist IDs and semantic ranges; markdown, prose and incomplete output fail. Existing authoritative domain/application validators then independently enforce their narrower use-case contracts (including the current per-draft exercise-link limit). Explicit commands still require their issued envelope, preview, bound confirmation, stale checks and typed gateway. No partial write or automatic retry occurs.

Timeout and explicit `cancelPending()` cancellation produce distinct failures. Runtime unavailable, model missing, digest mismatch, malformed JSON and crashes also reject the request. Trainer proposals remain transient; Settings reports the failure. Fake can be selected explicitly by tests/dev composition, but there is no automatic fallback that could create a misleading real-model result. Normal application and Tracking functions remain usable.

Normal inference uses only loopback HTTP. The adapter contains no non-loopback endpoint, pull/install/update operation or prompt/output logging. During one actual synthetic warm Phi request, a best-effort `Get-NetTCPConnection` sample of the temporary Ollama and llama-server process IDs observed only a `127.0.0.1` listener and established loopback connection (`NON_LOOPBACK_COUNT=0`). This is a point-in-time process/socket observation, not packet-level proof and not a guarantee about unrelated Ollama update behavior. The benchmark downloads were an explicit setup action; inference after installation requires no Internet. Packet-level verification and managed-sidecar packaging remain production release gates.
