# ReportSelection v1

Foundation: `33a67a2414aebe61a254305a5b1b1dd1d2eb069f`. This slice changes report selection only.

## Contract

`reportSelection({ snapshot: { exerciseLibrary, workouts, templates }, recentFrom, asOf, limit? })`
returns `{ asOf, recentFrom, reportSelectionVersion, selectedExercises, excludedExercises, eligibleExerciseCount }`.

Dates are explicit inclusive ISO calendar dates, validated without the current clock. Limit is optional (all eligible exercises), or a non-negative integer, applied only after evaluation/ranking. Zero returns no display rows with `DISPLAY_LIMIT` diagnostics. The underlying history and classification APIs remain unrestricted.

Each selected item contains exact `exerciseId`, `selectionReasons`, the existing `progress` result (status, reasonCodes, algorithmVersion, current/comparison exposures and reference/set evidence), active-template IDs, recent exposure references, and ranking metadata. Analytics contains no labels, colors, CSS or coaching recommendations. Version is `report-selection-v1`.

## Universe and reasons

Every distinct library ID is checked with Core's strict identity classification; ambiguous/invalid IDs are excluded. The candidate union is:

- An exact valid reference in a currently persisted template. The model has no active flag or historical template membership, so current templates define active membership even for a historical report window.
- At least one Core/Analytics exposure in `[recentFrom, asOf]` containing a finite weight/reps pair. Skipped, empty, unresolved and partial-only exposures cannot by themselves admit an inactive exercise.

History is read through ExerciseExposureHistory with enough capacity for all workouts as of the report date. Classification uses ExerciseProgressClassification unchanged, including searching beyond five exposures for comparable history. An older complete exposure does not replace an incomplete latest exposure when classifying.

| Reason | Supported evidence |
| --- | --- |
| RECENT_EXPOSURE | At least one recent complete-set exposure |
| ACTIVE_TEMPLATE | Exact valid current template reference |
| MEANINGFUL_CHANGE | PROGRESS or REGRESSION on a latest exposure inside the report window; no extra numerical threshold |
| NEEDS_ATTENTION | Recent REGRESSION, or FLAT with MIXED_SET_PERFORMANCE / PERFORMANCE_TRADE_OFF / SET_COUNT_CHANGED |
| INSUFFICIENT_COMPARABLE_HISTORY | INSUFFICIENT_DATA or NOT_COMPARABLE; original detailed reasonCodes preserved |

PERSONAL_RECORD and USER_PRIORITY are unsupported: no approved PR classifier or persisted exercise priority source exists. No persistence is invented. Unknown reference IDs absent from the library do not create candidates; excluded diagnostics enumerate library IDs, not every invalid workout/template reference.

## Deterministic ranking

Lexicographic ordering:

1. Priority tier, ascending: recent regression; recent mixed/trade-off FLAT; recent progress; recent not-comparable; recent insufficient data; recent stable FLAT; active-template-only without a recent classified exposure.
2. Most recent complete exposure date in the report window, descending.
3. Active-template membership, true first.
4. Original library source position, ascending. No ID/name sorting or special identities.

The priority tier is categorical selection metadata, not a Performance Score. True FLAT remains distinct from mixed/trade-off outcomes without modifying the existing enum. Stale progress/regression retains its original status but gains neither MEANINGFUL_CHANGE nor NEEDS_ATTENTION. A latest partial exposure may receive an insufficient-data priority; its original Analytics evidence remains visible. Same-date exposure ordering follows the existing Core/Analytics snapshot-order contract. Reordering input library records can change full ties; identical input always produces identical output.

## Desktop integration

`coachReportSelection` passes the snapshot and selected date range to policy and attaches current definition labels. CoachReport consumes its ordered selection without a limit; no arbitrary row cap is introduced. The former `reportExerciseCandidates.ts` implementation is deleted. Existing active-template regressions exercise the new adapter. All current active template identities remain represented, and recent valid inactive exercises can now also appear.

Layout, chart code, report export, notes, and other pages retain existing behavior. Date inputs retain the previous valid interval when temporarily cleared or inverted. React row identity remains the canonical exercise ID.

## Technical debt and limits

- Existing CoachReport best-set comparison/presentation is not the new whole-exposure progress status. Selection preserves the Analytics status/evidence, but this slice does not migrate the legacy comparison column or expose selection reason labels in UI. Therefore ranking and displayed best-set delta can describe different evidence. A later report-presentation decision is needed.
- ExposureHistory currently rescans the snapshot and audits identities for each requested definition. This policy reuses it rather than duplicating grouping/filtering. A later measured batch optimization may help large histories.
- No historical template-membership snapshot or user-priority/PR source exists. No new data model is added.
