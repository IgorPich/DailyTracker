# Trainer text ingestion (manual, HumanCoach v1)

## Application boundary

The existing `createHumanCoach` service adds typed commands; no competing entities or extractor abstraction:

- `ingestTrainerText({ id, text, createdAt, sourceDescription? })` creates one CoachNote with `TRAINER_TEXT` provenance. The caller supplies a fresh identity and canonical UTC timestamp. Optional sourceDescription uses the existing sourceReference field. Empty/whitespace text fails existing validation; the application does not trim, parse, normalize, hash or deduplicate text. Duplicate IDs fail, while identical messages with distinct IDs are separate notes. It returns the persisted HumanCoachContext, like existing creation commands.
- `createDraftFromNote({ id, sourceNoteId, createdAt, kind, ...structuredFields })` takes a discriminated TASK/TARGET/DECISION input and delegates to existing creation commands. It resolves an exact CoachNote ID, inherits that note's source type, and stores the exact sourceNoteId. Manual-source notes remain MANUAL, trainer-source notes remain TRAINER_TEXT. No note text is extracted or copied into structured fields automatically. The domain validates source chronology and exact existing exercise references.
- `discardCoachDraft({ id })` removes only a structured DRAFT. NOTE and AUTHORITATIVE entries cannot be removed with this command. It never removes source evidence. This is local draft rejection, not a synced tombstone or accepted-task status transition.

Manual UI and a future extractor can use the same typed draft input. No AI/model/prompts/regex extractor is present. The application has no Tracking write port, only read-only exact exercise IDs.

## Safety and storage

Existing base construction always creates DRAFT; caller-supplied acceptance cannot override it. Only the separate explicit acceptCoachItem action makes an item AUTHORITATIVE. Source-note acceptance does not accept its derived items. Existing repository protection rejects overwriting/removing note text and provenance. Cancelling every derived draft leaves the source intact.

There are **no new persisted fields, entities, files, versions or migrations**. All records fit the existing version:1 model and validator. The existing PC-local write queue, single-instance safeguard, atomic replacement and backup remain unchanged. Browser/development storage remains isolated. No Mobile or sync changes.

The application preserves supplied text exactly, including CRLF and whitespace. Desktop uses an HTML textarea: its text value may normalize pasted line endings to LF at the browser input boundary; the application performs no further normalization. Text is rendered as escaped plain text, never executed or interpreted.

## Desktop

The existing Kontekst trenera form defaults to trainer-text ingestion with “Wklej wiadomość / zalecenia trenera”. Saved notes display immutable source text, source type, description and timestamp. Each note provides Task/Target/Decision draft actions that pre-link only its ID and open blank structured fields. The draft form and saved items link back to the source details. Save and acceptance remain separate buttons. Discarding a stored draft requires confirmation.

Exercise linking reuses ExercisePicker; search is discovery-only, explicit selection passes the persisted definition ID. Names and aliases never resolve identity. Same-name definitions remain independent. If a definition is absent, guidance directs the user to the existing explicit creation/save workflow in Training. This screen cannot create exercises. An exercise-scoped target cannot save without a selection; the application also validates references.
