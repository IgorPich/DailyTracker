# Companion read-only runtime

Foundation and persistent safety checkpoint: `53f360352799771dbe4b0a9710064536dc6de42d`.
The checkpoint is a branch, not a release. This slice adds no command action.

## Capability contracts

The separate `@greekgod/companion/readonly` entry point exports three handlers:

| Handler | Issued input | Meaning |
| --- | --- | --- |
| dialogue | `UserDialogueInput { kind: 'USER_DIALOGUE', text }` | Deliberate informational question |
| spontaneous | `SpontaneousCompanionTrigger { kind: 'SPONTANEOUS_COMPANION', reason: 'CONTEXT_AVAILABLE' }` | Explicitly supplied opportunity for informational output |
| applicationEvent | `ApplicationEventTrigger { kind: 'APPLICATION_EVENT', event }` | Neutral `WORKOUT_SAVED` or `TRAINER_CONTEXT_UPDATED` fact |

Factories freeze inputs. Separate private WeakSets establish input provenance at runtime;
discriminated types reject interchange at compile time. Each input is consumed once,
before reading context. Forged/copied/cross-capability inputs fail closed. Existing
TrainerText and ExplicitUserCommand factories and workflows are unchanged.

This is application capability separation, not a security sandbox for hostile JavaScript
already running with arbitrary process access. The runtime imports only a type-only
model port. It does not import command code, mutation functions or platform services.

## Read side and provider

`CompanionContextReader.readEvidence()` returns only explicit `{ id, text }` evidence.
This is the only read port needed to prove these handlers. No speculative Analytics or
HumanCoach service dependency is added: future Desktop adapters can project already
calculated Analytics facts or trainer-authored context into these DTOs. Analytics remains
the calculation authority; the trainer/HumanCoach remains strategy authority.

Context rejects unknown fields, malformed entries and duplicate IDs. The provider
receives a detached `{ kind: 'COMPANION_READ_ONLY', input, evidence }` request through
the existing generic CompanionModel abstraction. No reader object, raw aggregate,
history, store, gateway or executor is passed to the provider. A provider cannot change
the original allowlist by modifying its detached request.

FakeCompanionModel remains configurable output only. There is no parser, routing by
text content, real model, network service or prompt engineering.

## Closed response

`CompanionReadOnlyResponse = { message: string, evidenceIds: readonly string[] }`.
Both fields are required; references may be empty. Text must be nonempty and references
must be unique members of the supplied allowlist. Unknown fields, actions, commands,
arbitrary payloads, malformed arrays/objects and invented references are rejected.
The validated response is frozen. Failure returns INVALID, never a partial response,
automatic retry or fallback action.

No response field is executable. Text that resembles a mutation remains inert text;
the runtime neither prepares a draft nor creates confirmation. A configured fake can
explain that a separate explicit-command workflow is required, but this is not a
keyword detector. A closed schema proves the absence of executable capabilities, not
the factual truth or strategic appropriateness of arbitrary generated prose. Real-model
content safety and factuality evaluation must be reviewed before adding a real provider.

## Desktop, events and persistence

No new Desktop surface is needed in this architectural slice: tests exercise all three
handlers with explicit reader fixtures. There is no chat transcript, automatic event
subscription, event bus, persistent event log or spontaneous schedule. Existing explicit
command UI is unchanged and remains the only Companion mutation-capable workflow.
Read-only processing itself is platform-neutral and safe with browser/legacy contexts;
it receives no persistence capability. Existing browser/legacy command execution remains
blocked by the approved command gateway.

No changes to Tracking, HumanCoach, Analytics, Mobile, storage schema or sync protocol.
No task completion, automatic recommendations or production data access.

## Verification

The regression suite covers all three inputs, deterministic output, mutation-like text,
compile/runtime envelope separation (including rejection by command preparation),
closed schema, unknown evidence, context/provider failure, detached context and
immutable results. Import regression restricts every read-only module to the type-only
model port and checks extraction/barrel isolation. Existing extraction, command and
Desktop queued-persistence regressions remain part of the full repository gates.

Deferred: Desktop read-side adapters/UI and event wiring when needed, real provider,
memory/transcripts, ReactionCoordinator/avatar, semantic presentation metadata,
content-safety evaluation and any further command. No automatic escalation to command
capability is permitted by this design.
