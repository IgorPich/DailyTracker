# Exercise picker and weight-trend UX

Based on deterministic foundation/checkpoint `d1339210475fdaaa0c65daa6e71796898f39e121`. The checkpoint is a branch, not a release tag or release-readiness claim. HumanCoach feature development remains paused.

## Desktop picker

`ExercisePicker.tsx` provides one small combobox for template replacement, active-session replacement, saved-workout replacement and Progress. `exerciseSearch.ts` owns discovery and explicit result selection. Search displays definition names; same-name records receive stable library-order variant labels and available recency/template/equipment context. Users never type a technical ID. Missing, whitespace-invalid or duplicate library IDs are not offered.

Discovery normalizes case, Polish diacritics (including ł), substrings and tokens. Bounded edit distance includes adjacent transposition; words of at least four characters allow one edit, words of at least eight allow two. Exact substring/token results precede fuzzy suggestions. Aliases are not used. Text filtering never changes identity, creates definitions or queries history by name. Clicking a result or explicitly navigating with arrows and pressing Enter selects its exact currently persisted ID. Enter on unhighlighted text does nothing. Selected ID is rechecked against the library before calling the consumer.

Progress includes all valid persisted definitions, not a hardcoded shortlist. Ordering: definitions with completed recorded set data, latest workout date first; then active-template membership; then original library order. Search relevance precedes this ordering when filtering. The previous hardcoded default exercise is removed. Selection of a definition without history displays the existing empty-history state. ExposureHistory, comparability, ProgressClassification, metrics and report ranking are unchanged. Recency metadata is only picker ordering, not a new Analytics verdict.

## Creation and replacement

New creation remains separate from the picker. Template, active-workout and saved-workout creation controls explicitly say “Utwórz nowe ćwiczenie”; creating requires non-empty name and confirmation before generating a new identity. Confirmation lists similar candidates generically and warns that a new definition has separate history. Enter while typing an active-workout creation name no longer invokes creation. No fuzzy merge/reuse or implicit canonical resolution occurs. Creation is staged until the existing template/workout save; cancelling its editor does not save new definitions. Template replacement offers persisted library entries, not unsaved draft-only definitions.

“Tylko ten trening” changes only the selected active occurrence, preserving its slot ID and switching exerciseId to the clicked definition. Existing confirmation before clearing entered sets is retained; fresh empty sets prevent carrying performance from the old exercise. `replaceSessionExercise` is a small presentation-workflow helper with no template input or writes. Saved-workout replacement retains its existing explicit edit/save semantics and set data; it is not an automatic historical repair.

“Zmień w szablonie na stałe” opens the existing template editor. Choosing a result uses Core `replaceTemplateExerciseDefinition`; the user still saves the template explicitly. Only the chosen reference changes from this action. Core identity, prescription/set-count retention and the existing no-global-rename behavior remain intact; other templates/history are not changed by replacement. Existing separate advanced template editing controls are not redesigned.

## Bodyweight characterization

Before modifying presentation, characterization tests ran on the original algorithm. A point on D averages finite observations in the inclusive calendar interval D−6..D, not the last seven recorded observations. Points are emitted for recorded weight entries; missing days do not create zero values or extra chart points. The display range filters output points only: observations just before its start still contribute to the first point's average. Existing unique-day Tracking semantics remain unchanged; this slice introduces no data cleanup/deduplication.

No mathematical change: the original moving-average expression remains untouched. Each point now adds read-only `windowFrom`, `windowTo` and `measurementCount` metadata using the same existing window. Coverage counts finite observations (normally one per day), not inferred/missing values. Existing chart data is not persisted. Tooltip retains daily/average values and adds the dated interval, `n/7`, and an explanation that the window ends on the hovered date and missing observations are not zero kg. Shared WeightTooltip benefits Dashboard and CoachReport without chart redesign.
