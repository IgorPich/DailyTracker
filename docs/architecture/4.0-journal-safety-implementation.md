# Journal safety — implementation milestone

Schema 8 is implemented on the feature branch, not deployed. Migration 7 checksums and
all prior migrations remain unchanged. New tables: daily_delivery (per remote/operation,
frozen original_remote_base, pending/needs_review/legacy_needs_review, observed revision)
and daily_conflict_rejections (authority operationId rejection ledger plus original request).
No DailyEntry payload migration, no fabricated measurements, no global revision increment
for conflict metadata alone. Migration executes in the existing SQLite transaction.

Pending client DailyEntries for registered outgoing sync_remotes are quarantined during
migration; acknowledged rows, unrelated entities and Desktop authority publication rows
(no outgoing sync_remotes) are not. Preparing an outgoing queue also quarantines missing
metadata, covering old unpaired queues. Unverifiable pre-pair operations remain preserved,
not assigned today's remote baseline. Authority outbox enumeration itself is unchanged.
Delivery metadata is frozen in the same transaction that creates new client outbox intent,
not on retry. Multiple pending edits against one unchanged remote baseline may conservatively
conflict after the first succeeds; there is no automatic same-entity rebase.

DailyEntry CAS conflict durably blocks that operation on PC and quarantines the Mobile
delivery before pull. Retry selection skips it without starving unrelated entities.
The registry blocks the same operationId even with modified payload/base and after reopen.
Successful idempotency remains separate. Other entity conflict behavior is unchanged.
Review entries are not counted as conflicts_resolved. Mobile Settings shows dates and
preserved payloads with instructions to sync/refresh and manually reapply as NEW intent.
Old records remain immutable review history, not silently acknowledged or deleted.

Local Mobile Journal uses explicit touched SET/CLEAR fields and a detached baseline.
The existing serialized provider queue loads current authority, checks only edited fields,
and overlays the patch on the fresh entry. Unknown fields survive; same-field conflict
rejects. A local CAS retry repeats validation; unknown acknowledgement never auto-replays.
React success follows persistence. Explicit refresh discards/reloads the draft.

Schema8↔schema8 is enforced by existing handshake; schema7 requests fail before mutation.
Protocol remains 1. No redundant capability flag: exact schema8 is the approved gate for
this coordinated Desktop/Sync/Mobile release. Old 3.x clients must remain with matching 3.x
authority. No production DB, phone, installed app or sync service was launched/migrated.

Verified milestone: all workspace typechecks; Mobile 17 tests; storage 54 tests including
schema7 role-sensitive migration and failure rollback; sync engine schema rejection and
idempotency tests; actual MobileSyncEngine over two native stores proves conflict/no replay,
unrelated-workout progress, repeat sync and reopen; Mobile native tests. Full slice gates
and Configurable Journal implementation still follow. Not a final completion report.
