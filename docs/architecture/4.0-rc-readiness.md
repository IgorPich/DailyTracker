## Production bundle blocker resolved on this branch

The production Settings surface still statically imported and displayed the
development-only Ollama transport and Fake-provider wording. It was not an
automatic fallback, but it violated the approved production boundary.

The narrow correction removes those imports, instances, status query, and UI
copy from product source. Managed-runtime behavior, model identity, prompts,
decoding, lifecycle, Companion authority, and storage/sync semantics are
unchanged. Regression checks now bind decoding assertions to the Rust managed
runtime (their real owner), reject Ollama product transport/imports, and require
Settings to expose only the managed runtime. The production bundle audit also
rejects dev inspection pages, smoke markers, cloud API hosts, and model/runtime
artifacts.

The resulting production-authority web bundle contains none of the following:
Fake provider/UI, Ollama transport/fallback/UI, Memory or reaction diagnostics,
physical-smoke harness/data, cloud API integration, GGUF weights, or llama
runtime binaries. Development and differential-test adapters remain outside the
production import graph.

## Versioning checklist

Current application version is 3.0.2 in `package.json`, workspace entries and
the root/workspace records in `package-lock.json`, Desktop and Mobile
`package.json`, Desktop and Mobile `src-tauri/Cargo.toml`, Desktop
`tauri.conf.json`, `tauri.production-authority.conf.json`,
`tauri.rehearsal.conf.json`, Mobile `tauri.conf.json`, and generated Android
`gen/android/app/tauri.properties`. Android currently uses
`versionName=3.0.2`, `versionCode=3000002`. The Sync Service and sync protocol
crate package versions are 3.0.1; internal storage/sync-client crates are 0.1.0.

Before a 4.0 RC/release:

1. Select the exact RC/release semantic version and Android monotonic
   `versionCode`.
2. Update the root, Desktop, Mobile, Tauri, and applicable Cargo package versions;
   regenerate npm/Cargo locks and Android `tauri.properties` through the normal
   Tauri process.
3. Update the production/rehearsal version assertions in
   `apps/desktop/scripts/development-storage-config.test.mjs`.
4. Update installer names and 3.0.2 instructions in `README.md`.
5. Add a 4.0 changelog/release-notes document (none currently exists).
6. Build and inspect new signed Desktop and Android release artifacts, then run
   an isolated 3.0.3 -> 4.0 upgrade rehearsal after policy decisions.

There is no separate visible application-version label in the Desktop or Mobile
UI today. Installer metadata is sourced from Tauri version configuration.
Desktop identifier stays `com.igorpich.formlog`; Mobile stays
`com.igorpich.greekgod.mobile`. Storage schema stays 8 and sync protocol stays 1;
neither changes merely because the product version becomes 4.0.
