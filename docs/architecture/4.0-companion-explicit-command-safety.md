# Explicit command safety: ChangeTemplateRepRange

Scope: one opt-in Desktop command, configurable FakeCompanionModel only. No real model,
natural-language parser, spontaneous actions, new storage schema or sync protocol.

## Contracts and capability boundary

`ExplicitUserCommandInput` is a frozen `{ kind: 'EXPLICIT_USER_COMMAND', text }`
issued by the explicit submit factory. A private WeakSet verifies and consumes its
provenance; a structurally similar CoachNote or copied envelope is rejected.
This is an application capability boundary, not a sandbox against arbitrary malicious
code already executing in the Desktop process.

The model receives only text and eligible candidate rows (exact template/slot/exercise
references, display labels, prescription). It receives no AppData, history, executor,
confirmation, persistence or gateway. Fake output is configured explicitly by the user;
it does not infer an action from text.

The separate `@greekgod/companion/commands` export contains the closed
`ActionDefinitionRegistry`: only `CHANGE_TEMPLATE_REP_RANGE`. The extraction barrel,
TrainerText extraction and HumanCoach UI do not import it. The output schema rejects
unknown fields/actions, invalid ranges, duplicate/unknown references and malformed
arrays. Names are presentation only, never identity resolution. Multiple offered
candidates require an exact user selection, never the first match.

The proposed draft is validated before becoming an `ActionPreview`. Its Core plan
contains action, exact template/slot/exercise IDs, old/new prescription, new min/max,
and the serialized original template. Core changes only that slot's prescription.
It preserves identities, set counts, ordering, all other template fields and history.
Only a simple single rep range, optionally prefixed by a set count, is supported.
Complex prescriptions and numeric no-ops are rejected, not flattened or normalized.

## Confirmation and persistence

Preview and plan are frozen. Deterministic confirmation content includes the entire
plan; runtime object identity additionally binds the single-use confirmation to this
session. Editing/cancelling/replacing a preview invalidates prior confirmation.
Execution consumes it before awaiting persistence. Enter never executes a mutation.

`TrackingCommandGateway` exposes only a capability flag and
`changeTemplateRepRange(plan)`, not a generic update/patch dispatcher.
Browser and legacy adapters can prepare/preview but execution is BLOCKED.

The native adapter uses its existing serialized queue for ordinary saves, loads,
polling, imports and the command. Inside that queue the command reads fresh authority,
recreates/compares the plan, then performs one existing authoritative replacement with
the fresh global revision as CAS precondition. A changed template invalidates the
preview; unrelated current data is retained. A concurrent native writer losing the
CAS race cannot be overwritten by the command.

`DesktopDataCoordinator` coordinates publication, not a second durable queue.
Ordinary edits submitted during execution are held and rebased after reconciliation.
Committed command data is published without saving it again. The former general React
autosave effect is replaced by explicit ordinary-update saves, preventing a duplicate
command write. Generation checks prevent an older poll overwriting a newer UI update.

## Outcomes and recovery

| Result | Meaning | Next step |
| --- | --- | --- |
| APPLIED | Verified acknowledged authoritative persistence | Show receipt and committed state |
| STALE | Target changed or known CAS conflict; zero command mutation | New preview/confirmation |
| FAILED | Known no durable command mutation, or invalid unexecuted confirmation | Newly validated attempt only |
| INDETERMINATE | Write may have committed but acknowledgement is not provable | No automatic replay; read authority |
| BLOCKED | Safe adapter unavailable or another command pending | Preview only / wait |

When reconciliation is unavailable, command execution is blocked and ordinary edits
remain held. After authority is recovered, the UI displays its observed prescription
and whether the exact target contains the requested state. This is evidence of current
saved state, not retrospective attribution of an unacknowledged write as APPLIED.
If the requested state is absent, a fresh preview and confirmation are required.
Reconciliation itself performs no corrective mutation or command retry.

`AppliedActionReceipt` contains action, three exact target IDs, before/after prescription,
acknowledgement time and resulting authoritative revision. It is session-local; no new
persisted audit schema is introduced. Internal IDs are tucked into technical details.

## Verification and deferred decisions

Regression fixtures exercise the full explicit-envelope/fake/preview/confirmation/
coordinator/authority path, single consumption, ambiguity, malformed output, forged
envelopes, legacy blocking, exact identity preservation, queued stale validation,
durability-before-publication, exactly one command write, ordinary edit ordering,
disk failure, CAS conflict, lost acknowledgement and blocked/recovered reconciliation.
Static UI/capability tests supplement these; they are not an interactive Tauri smoke.

Run the full repository test/typecheck and normal frontend build gates. No production
application, database repair, phone sync or installer is needed for this verification.
Native schema/protocol and protected release branches remain outside this slice.

Deferred: real model integration/timeouts, further actions, richer prescription grammar,
persistent receipts/idempotency ledger and cross-restart command recovery. No automatic
replay is introduced as a substitute for any of these decisions.
