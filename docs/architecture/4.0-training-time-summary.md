# TrainingTimeSummary v1

## Persisted semantics and limitation

Core `Workout.duration?: number` stores optional minutes. Desktop entry/edit labels use minutes with an HTML minimum of 1; imports do not enforce that minimum. Fractions are representable. Mobile creation does not supply duration. Legacy/imported records may omit it. No automatic timer or timestamp inference is used here.

The current Workout model has no persisted completion state. Mobile persists the record at start; finalization filters sets without persisting a completion marker. Desktop also allows partially performed sessions to be saved. Therefore TrainingTimeSummary v1 summarizes **recorded workout records and measured duration coverage**, not verified completed sessions. A future explicit workout lifecycle/completion field may refine this metric; this slice adds no such field or migration.

## Public contract

`trainingTimeSummary({ snapshot: { workouts }, from, to, asOf })` accepts a readonly projection of Core Workout (`id`, `date`, `duration`). It returns:

- `from`, `to`, `asOf`;
- `recordedWorkoutCount`: all persisted records with valid workout calendar dates in the interval, irrespective of sets, identities, template or presumed lifecycle;
- `workoutsWithDuration`: finite numeric duration strictly greater than zero;
- `workoutsWithoutDuration`: all remaining records (missing and invalid are deliberately combined);
- `totalDurationMinutes`: sum of usable durations only, zero when none exist;
- optional `averageDurationMinutes`: total divided by usable-duration count; property absent when that count is zero;
- `coverage: { numerator, denominator }`: usable-duration count / recorded-record count, including explicit 0/0 for an empty interval;
- `evidenceWorkoutIds`: contributors to the duration sum, sorted by date then exact ID.

No names, aliases, exercise identity inference, completion inference, normalization, writes, clock access or storage dependencies. Analytics imports only a Core type. Existing exercise comparability/grouping remains untouched and is not needed for this workout-level metric.

Dates are explicit ISO calendar dates; boundaries are inclusive. Require `from <= to <= asOf`, otherwise throw RangeError. `asOf` is a caller-supplied date horizon, not reconstructed historical storage state. Invalid record dates cannot belong to a valid interval and are excluded without mutation. Results use a stable date/ID order; numeric overflow throws rather than returning Infinity. The authoritative store provides unique workout IDs; the query counts supplied records, not inferred/deduplicated sessions.

## Desktop presentation

One independent Dashboard card, using the existing styles plus four scoped rules. Presets are presentation-only: month-to-date, year-to-date, all available valid dates through today, and a custom inclusive range ending no later than today. Empty all-time data uses today/today and displays an explicit empty state.

The card says “Zapisane treningi”, “Łączny zapisany czas”, “Średnio (z dostępnym czasem)” and shows measured/recorded coverage. Missing/invalid durations produce a visible incomplete-data explanation; zero usable durations display a dash rather than a misleading measured zero. Display rounds to whole minutes (positive values below half a minute show `< 1 min`); hours never wrap at 24. Analytics retains numeric minute precision. Range controls are local React state, not persisted/synchronized.
