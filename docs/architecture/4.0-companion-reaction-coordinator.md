# Semantic reaction coordination v1

Foundation: `2436d3c45631f68d795527b3543241dbe29440c4`, preserving both approved
structured-memory commits. Reaction state is session-only presentation state.

## Contracts and ownership

SemanticReaction is closed: NEUTRAL, ACKNOWLEDGE, POSITIVE, CONCERNED. These express
generic meaning, not exercises, performance thresholds, coaching strategy or animation.

ReactionRequest contains id, semanticReaction, source, priority, createdAt and up to
16 evidenceIds. Source is USER_DIALOGUE, SPONTANEOUS, APPLICATION_EVENT or COMMAND_OUTCOME.
Priority is LOW, NORMAL or HIGH. Requests are validated, copied and never contain
arbitrary model payloads. Evidence IDs are opaque application-provided references;
the coordinator neither resolves identity nor interprets the underlying facts.

V1 deliberately selects reactions in deterministic application policy, not the model.
The existing closed read-only schema is unchanged and rejects reaction, asset, CSS,
timing, priority and other unknown fields. FakeCompanionModel remains the only provider.

| Safe result source | Reaction | Priority |
| --- | --- | --- |
| Dialogue/spontaneous MESSAGE | ACKNOWLEDGE | LOW |
| Dialogue/spontaneous INVALID | CONCERNED | LOW |
| Application-event MESSAGE / INVALID | ACKNOWLEDGE / CONCERNED | NORMAL |
| Confirmed command APPLIED | POSITIVE | NORMAL |
| Command FAILED / STALE / INDETERMINATE / BLOCKED | CONCERNED | HIGH |

This is UI feedback, not a judgement on training or the trainer. TrainerText does not
publish reactions automatically. No progress calculation or autonomous recommendation
is introduced. Additional semantic reactions may be reviewed when there is a real need.

## Deterministic policy

REACTION_POLICY_V1: lifetime 3000 ms, cooldown 8000 ms, queued expiry 10000 ms,
queue capacity 8. The caller supplies nonnegative integer monotonic time. The domain
does not read Date, browser, OS, settings or clocks. Future requests and backward time
are rejected. Desktop supplies `performance.now()` through its presentation adapter.

- Neutral fallback has no token/start time; submitting NEUTRAL cannot interrupt feedback.
- Repeated semantic+priority keys inside cooldown are suppressed across sources.
- Queued duplicates coalesce by semantic+priority (or identical request ID).
- Higher priority replaces current; the interrupted reaction is discarded, not replayed.
- Equal/lower priority queues without interrupting current.
- Queue ordering is priority descending, creation time ascending, then exact ID.
- Capacity drops the lowest-ranked entry. Queued entries expire at age >= 10000 ms.
- Expired current reactions release the slot; the highest eligible queued reaction starts
  at the supplied observation time. Without one, presentation becomes NEUTRAL.
- Cooldown history is bounded by the closed semantic/priority set. Counters and queue are
  diagnostic in-memory state, not persisted history or Companion Memory.

Identical requests and observation times produce identical state. Polling cadence is
part of the explicit input sequence; long-paused presenters discard obsolete reactions.

## Presentation and Desktop

AvatarPresentationState contains semanticReaction, token, startedAt and reducedMotion.
Reduced motion is explicit input and does not alter semantic selection, queue, cooldown
or tokens. A future local AvatarPresenter will own assets and map this DTO to static or
animated presentation. There are no assets, colors, CSS classes, animation names or
component names in model output/domain state.

`Reakcje Companion` is a small text-only diagnostic card: current meaning, queue size,
suppressed/expired counters, reduced-motion toggle and buttons for three clearly labelled
synthetic read-only fake paths. Its 250 ms refresh timer is Desktop presentation plumbing,
not model/domain policy. It is cancelled on unmount. Both modes are text-only placeholders.
No OS-setting reader is added to the domain; final accessibility integration is deferred.

The explicit command page calls the optional observer only after awaiting the existing
confirmed execution result. POSITIVE is mapped only from APPLIED. Preview does not publish
success. All failure states produce presentation feedback only, with no retry, recovery
write or status conversion. Presentation errors are caught inside the observer so they
cannot turn a committed command into FAILED.

No general event bus, automatic workout subscription or autonomous reactions are added.
The diagnostic surface exercises the existing safe input paths without saving a workout.

## Capability proof and verification

Reaction domain modules have no imports at all: no model, command registry, gateway,
executor, persistence, memory or platform services. Desktop passes primitive safe outcomes,
not a mutation capability. Read-only handlers and TrainerText retain their existing
boundaries; command targeting/confirmation and Memory persistence are unchanged.

Tests cover closed requests/schema, cooldown boundary, preemption, coalescing, queued
expiry, neutral fallback, deterministic reduced-motion state, generated evidence IDs,
command outcome mapping, read-only fake paths and memory immutability. Static Desktop
regression checks result-before-observer ordering and capability imports; prior command
durability tests remain part of the full suite. No interactive avatar/Tauri smoke is claimed.

Deferred: final AvatarPresenter/assets, OS preference wiring, richer semantic vocabulary,
real model, actual app-event subscriptions, further command actions and reaction history.
No new storage/file/schema/sync/Mobile behavior. CoachReport trade-off copy/color remains
backlog-only and unchanged.
